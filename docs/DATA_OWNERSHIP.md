# Field Theory Local Data Ownership

Status: B2 documentation contract. This file records the intended single-writer boundary; it does not add enforcement by itself.

The practical rule is simple: every core shared local path should have one owning surface for writes. Other surfaces may read it, open it, or request a write through the owning surface, but they should not silently mutate the same files through a second path.

## Known Conflicts To Enforce Later

1. Implement or remove the advertised `ft current update --stdin --expected-sha256 <sha>` contract. The app and plugin currently tell agents to use it, but the local CLI help only shows read-only `ft current`.
2. Block generic CLI Library mutations from app-owned shared-cache subtrees such as `River (shared)` unless the write is routed through a River-aware API.
3. Keep X bookmark sync files CLI-owned while preserving the app-owned web bookmark index under `bookmarks/web/`.
4. Do not enforce River ownership against `~/.fieldtheory/shared/**` unless the code starts using that root as the sync cache. The current default writer uses `~/.fieldtheory/library/River (shared)/**`.
5. Decide whether `Commands/**` stays intentionally shared-write or gets a single owner. Today both the app and CLI can write command files.
6. Add cross-process locking only where real concurrent writes happen. The first enforcement layer should be namespace checks and expected-hash guards, not a broad lock around the whole Library.

## Update Rule

When this contract changes, update the app repo copy at `mac-app/docs/DATA_OWNERSHIP.md` in the same change.
